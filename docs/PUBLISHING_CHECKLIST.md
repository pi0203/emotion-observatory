## 1. 커밋 이력의 비밀 값 · 확인함 (완전하지 않음)

2026-10-10에 모든 브랜치의 커밋 32개를 읽기 전용으로 검사했다. 도구는 설치하지 않았다.

- `git log --all -- '.env*' '*.env' '.vercel'`: 이력에 `.env` 파일이나 `.vercel` 폴더가 들어간 적이 **없다**.
  로컬에는 `.env.local`이 있지만 `.gitignore`(`.env*`, `.vercel`)로 추적되지 않는다.
- `git log --all -p`의 추가된 줄에서 흔한 비밀 값 형태를 찾았다: `sk-`, `sk-ant-`, `ghp_`, `github_pat_`, `AKIA`, `AIza`, `xox?-`, `-----BEGIN ... PRIVATE KEY`, JWT 형태(`eyJ...`), `VERCEL_...=`, `SUPABASE_...=`, `api_key / secret / password / token = 긴 값`. **모두 0건**이었다.
- 40자 이상의 긴 문자열은 230건 나왔고, 모두 `package-lock.json`의 패키지 무결성 값(`"integrity": "sha512-..."`)이었다. 비밀 값이 아니다.

**한계:** 정해진 형태만 찾는 한 번의 검색이다. 형태가 다른 비밀 값, 인코딩된 값, 앞으로 생길 커밋은 잡지 못한다.
공개 직전에 한 번 더 검사하고, 가능하면 GitHub의 비밀 값 검사(secret scanning) 기능도 켠다.

## 2. 이력 안의 논문 PDF와 이미지 · 확인함

- `git log --all --stat -- papers`: `papers/` 아래 파일이 커밋된 적이 **없다**.
- 이력 전체에서 `.pdf`, `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.zip`, `.hwp`, `.doc(x)` 파일을 찾았다: **없다**.
- 원칙: 논문 PDF와 디자인 참고 이미지는 저장소에 넣지 않는다([THIRD_PARTY.md](THIRD_PARTY.md)).

## 3. 커밋 작성자 이메일 · 확인함, 처리는 사용자 결정

- 커밋 32개 모두 작성자 이메일이 개인 이메일 주소로 기록되어 있다. 저장소를 공개하면 이 주소가 누구에게나 보인다.
- 파일 **내용** 안에는 이 주소가 들어 있지 않다(이력 전체 검색, 0건).
- 공동 작성 표시(`Co-Authored-By`)에는 `noreply@anthropic.com`이 들어 있다. 개인 정보가 아니다.
- 선택지(사용자가 정한다):
  - 그대로 공개한다.
  - **앞으로의 커밋만** GitHub noreply 주소로 바꾼다. GitHub 설정의 Emails에서 "Keep my email addresses private"를 켜고, 그 주소를 `git config user.email`로 쓴다. 이미 공개된 이력의 주소는 그대로 남는다.
  - 이미 있는 이력의 주소까지 바꾼다. 이력을 고쳐 쓰는 일이라 커밋 해시가 모두 바뀐다. 이 점검표의 작업 범위 밖이며, 할지는 사용자가 정한다.

## 4. 제3자 자료 · 확인함

- 한국어 정서 점수 자료는 **현재 저장소에 없다**([NORMS.md](NORMS.md), 어휘의 `normStatus`는 모두 provisional).

## 5. 수업, 학교와의 관계 · 확인 필요 (공개를 막지는 않음)

- **교수님께는 공개한 뒤에 알린다.** 교수님 확인은 공개의 조건이 아니다.
- **사전 확인이 필요한 것은 동료의 정보를 모으는 일뿐이다.** 수업 채널(A)처럼 동료의 이름, 이메일, 이용 기록을 모으는 기능은 만들기 전에 교수님께 확인한다([LOGIN_DECISIONS.md](LOGIN_DECISIONS.md) 11번). 저장소 공개는 동료의 정보를 모으지 않으므로 여기에 해당하지 않는다.
- 수업 과제나 학교 지원으로 만든 결과물에 대한 학교의 권리 규정: **확인 필요(공개를 막지는 않음)**. 확인 결과 라이선스 표시를 고쳐야 하면 그때 고친다.
