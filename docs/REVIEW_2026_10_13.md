# 감정 관찰실: 배포 전 화면·안전 검토

검토일: 2026-10-13. 임상심리 대학원생, 「AI와 디지털 심리치료」 수강생, 지도교수의 검토 관점을 적용했다. 교수님의 실제 평가나 임상적 승인이라는 뜻은 아니다.

## 후속 검토: 사용자가 제공한 최신 (나) 카드형을 우선 기준으로 삼음

최신 미리보기: https://emotion-observatory-git-claude-landing-crisis-card-eunchanjoe.vercel.app/ . 아래의 최초 로컬 검토와 서로 다른 작업본이다. 실제 배포 SHA는 아직 확인하지 않았다. (가) 시안은 아직 코드/URL이 없어 검토하지 않았다.

### 최신 미리보기에서 해결되거나 개선된 점

- 카드형 레이아웃과 배지 스타일이 실제로 적용되어 있다. 최초 로컬 코드의 CSS 누락 지적을 이 미리보기에 그대로 적용하지 않는다.
- ‘이 도구에 대하여’와 ‘참고한 연구 6편’, FAQ가 실제 화면에 연결되어 있다.
- 연구마다 결과와 한계를 구분하고, 프리프린트 여부와 앱 자체 효과 미검증을 표시한다. 이번 검토에서 해당 논문 원문을 다시 검증한 것은 아니다.
- FAQ에는 브라우저 저장이 암호화되지 않음, 브라우저 데이터 삭제 시 기록 소실, 반추/불편감과 중단에 관한 설명이 있다.

### 최신 미리보기에서 남은 우선 보완점

1. **무응답 표시 오류 (새로 재현):** 깊은 관찰의 전체 느낌을 ‘건너뛰기’하면 실제 저장값 `deepReflection.affect`는 빈 객체 `{}`인데, 요약 및 요약의 관찰 문장에는 ‘중간 · 중간’으로 표시된다. 중립을 선택한 사람과 응답하지 않은 사람을 구별해야 한다. 건너뛰기는 ‘기록하지 않음’, 잘 모르겠음은 그 자체의 응답으로 유지한다. 이 둘을 중립 좌표로 바꾸거나 빈 값을 중립처럼 표시하지 않는다. 직접 깊은 관찰을 시작했는데도 전체 느낌 안내가 ‘빠른 확인에서 표시한 곳이 먼저 놓여 있습니다’라고 나오는 점도 조건부 문구로 고친다.
2. **악화 보고 후의 경로:** ‘더 불편해짐’ + ‘도움되지 않음’ 후에도 일반 요약과 추가 성찰 질문이 나온다. 이 시점에서는 성찰을 더 하지 않고 마치거나 선택적으로 도움 안내에 접근하게 한다.
3. **초안 교체 확인:** 검토용 빠른 확인 초안을 만든 뒤 새 깊은 관찰을 시작하면 확인창 없이 초안 ID가 교체됨을 실제 저장 상태로 확인했다. 이전 초안 보존 또는 명시적 폐기 선택이 필요하다.
4. **첫 카드의 개인정보 표현:** 자물쇠·‘비공개 · 이 기기에만 저장’ 표시는 그대로다. FAQ에 한계가 있어도 첫 카드의 보호 보장 인상을 해소하지 못한다. 암호화되지 않은 브라우저 저장임을 첫 카드 가까이 표시한다.
5. **모바일 카드 높이:** 375×667px iframe에서 첫 시작 버튼의 위치가 위 641px~아래 693px로, 처음 보이는 화면에서 일부가 잘린다. 데스크톱 브라우저의 스크롤바 때문에 프레임의 실제 콘텐츠 폭은 360px였다. 실제 휴대폰 실측이 아니라 제한된 브라우저 프레임 검토다. 모바일 배지 수/배치, 제목 크기 및 내부 여백을 줄여 주요 시작 행동이 온전히 보이도록 검토한다.

### 추가 개선

- 참고 연구에 DOI 또는 원문 링크를 연결해 확인 가능성을 높인다. 이번에 펼친 연구 목록에는 논문 제목이 텍스트로 표시됐고 원문 링크는 없었다.
- FAQ 또는 설명 영역에서 현재 앱 요약이 규칙 기반임을 알린다. AI를 이용한 개발과 앱의 사용자 데이터에 대한 AI 추론을 구분한다.
- 현재 방향은 (나)를 다듬는 것이며, (가)의 추가 브랜치/배포는 아직 필요하지 않다. 모바일 문제를 보완한 뒤 비교할 이유가 생기면 그때 요청한다.
- 검토 중 미리보기 origin의 앱 저장 키를 먼저 백업했고, 종료 시 동일한 이전 저장값으로 복원되었음을 확인했다. 운영 origin의 기록은 변경하지 않았다.
- 앞서 407개 테스트 통과와 빌드 성공은 최초 로컬 `design-lab-blue` 작업본의 결과다. 이 최신 미리보기 브랜치의 코드/테스트/빌드 결과로 간주하지 않는다.

**후속 상태:** (나) 카드형의 방향은 유지할 수 있으나, 무응답 표시·악화 후 경로·초안 보존·개인정보 표현을 고치기 전에는 운영 반영 승인을 권하지 않는다. Antigravity는 이 후속 항목을 우선 구현하고 같은 미리보기 주소를 갱신한 뒤 알려준다.

## P0: 다음 미리보기에서 먼저 보완할 것

### 1. 개인정보 안내의 정확성

대상: `lib/i18n/messages.ko.ts`의 `landing.badgeLocal`, `landing.storageNote`; `app/(ko)/page.tsx`의 `LandingScreen`.

- ‘비공개’ 및 자물쇠가 암호화나 접근 통제를 보장하는 것처럼 보이지 않게 바꾼다.
- 시작 버튼 가까이에서 이 브라우저에 저장됨, 암호화되지 않음, 공용 기기 이용 주의, 브라우저 데이터 삭제 시 소실을 안내한다.
- 내보내기 파일도 암호화되지 않는다는 기존 안내는 유지한다.
- 사용자가 한 번의 링크/버튼으로 지난 기록과 삭제 방법에 접근할 수 있게 한다.

승인 기준: 첫 화면만 읽은 사람도 ‘다른 사람이 같은 기기/브라우저에 접근하면 기록이 노출될 수 있다’를 이해할 수 있다. 안내 문구와 실제 저장 방식이 일치한다.

### 2. 불편감 증가·중단 시 성찰을 강요하지 않는 경로

대상: `OutcomeScreen`, `SummaryScreen`, `StoppedScreen`; `lib/i18n/messages.ko.ts`.

직접 재현: 빠른 확인 → 깊은 관찰 → 몸/느낌/상황/중요했던 것/표현 건너뛰기 → ‘더 불편해짐’ + ‘도움되지 않음’ → 다음. 일반 요약과 ‘다음에 생각해볼 질문’이 그대로 나오며 전용 악화 안내는 없었다. 중단 화면에는 전문 도움 안내가 없었다.

- ‘더 불편해짐’ 선택 시 즉시 알아볼 수 있는 ‘여기서 마치기’와 선택적인 도움 경로를 제공한다. 추가 질문을 반드시 읽거나 답하게 하지 않는다.
- 악화 보고 후에는 일반적인 추가 탐색 권유를 우선 행동으로 두지 않는다.
- 중단 화면에서도 원하면 도움 안내에 접근할 수 있게 한다.
- 이를 위험 판별, 진단 또는 응급 모니터링 기능으로 표현하지 않는다. 자동 키워드 위험 점수 기능을 만들지 않는다.
- 위기 연락처의 지역, 적용 대상, 운영 시간은 공식 출처로 확인한 뒤 표시한다. 현재 코드에 들어 있다는 사실만으로 검증 완료라고 간주하지 않는다.

승인 기준: 악화 선택 후와 중단 후 모두, 추가 성찰 없이 마치거나 도움 안내를 볼 수 있다. 악화 보고에 특화된 UI 회귀 테스트를 추가한다.

### 3. 기존 이어하기 초안 덮어쓰기 방지

대상: `App`의 새 시작 핸들러, `LandingScreen`, `lib/storage.ts`, `lib/session-types.ts`.

현재: 하나의 초안 저장 키를 사용하며, 초안이 있을 때 새 빠른 확인/깊은 관찰을 시작하면 새 세션 저장이 이전 초안을 대체할 수 있다.

- 이전 초안이 있을 때 ‘이어하기’ 또는 ‘기존 초안을 버리고 새로 시작하기’를 명시적으로 선택하게 한다.
- 취소 시 이전 초안과 완료 기록을 변경하지 않는다.
- 새 기록 시작을 확인하기 전에는 이전 초안을 덮어쓰지 않는다.

승인 기준: 초안 A가 있는 상태에서 새 시작 → 취소 → A 이어하기가 가능하다. 빠른 확인/깊은 관찰 모두 테스트한다.

### 4. 효과·AI·근거 경계와 첫 화면 스타일 정리

대상: `LandingScreen`, `lib/i18n/messages.ko.ts`, `app/globals.css`, `lib/synthesis.ts`.

- 효과 미검증과 의료/위기 대응 도구가 아님을 짧게 첫 화면에 드러낸다. 현재 효과 한계는 펼침 안에 있어 쉽게 지나칠 수 있다.
- 요약은 규칙 기반이며 AI가 감정을 추론하는 것이 아니라는 점을 설명한다. AI로 개발했다는 사실과 앱에서 AI를 사용한다는 사실을 섞지 않는다.
- 연구 배경, 임시 한국어 어휘/후보 규칙, 이 앱 자체 효과의 미검증을 구분한다. 단어 수나 만족도 증가를 치료 효과로 표현하지 않는다.
- 기존 요약의 ‘관찰한 것 / 아직 알기 어려운 것 / 사용자 수정’과 비인과적·비진단적 경계는 유지한다.
- ‘이 도구에 대하여’ 영역의 복원/제외를 명시적으로 결정하고 최신 화면과 코드가 일치하도록 한다. 자료를 붙인다면 실제 확인된 출처와 한계를 함께 표시한다.
- 새 첫 화면 클래스의 스타일을 정의하거나 기존 스타일로 통일한다. 모바일에서 배지를 읽기 쉽게 분리한다.

승인 기준: 첫 화면에서 목적과 한계를 함께 알 수 있다. 카드·배지·개인정보·위기지원 영역은 미정의 클래스에 의존하지 않는다.

## P1: 모바일과 사용성

- 375×667 CSS 픽셀 iframe에서 렌더링한 결과, 빠른 확인의 ‘다음’ 버튼이 최초 화면 아래에 있다. 실제 기기/Safari 테스트를 한 것은 아니다.
- 제목·안내·단계 상단 여백을 줄여 좌표판과 진행 행동이 가능한 한 함께 보이게 검토한다. 버튼을 고정한다면 좌표판이나 도움 안내를 가리지 않는지 확인한다.
- 첫 화면의 개인 홈페이지 메뉴는 관찰 진입을 방해하지 않는 수준으로 유지한다. 풀이 도중에는 기존 최소 머리말 유지.
- 375px와 1280px, 밝게/어둡게에서 가로 넘침, 선택 상태, 포커스, 대비, 내용 잘림을 비교한다.

## 이번 검증 범위와 결과

- 현재 로컬 첫 화면과 운영 첫 화면을 직접 확인했다.
- 로컬에서 빠른 확인의 좌표 선택 → 후보 → ‘가까운 말이 없음’ → 요약 → 깊은 관찰 6단계 → 악화 보고 후 요약까지 재현했다.
- 375px 프레임에서 로컬 첫 화면, 빠른 확인, 중단 확인창, 중단 화면을 확인했다. 운영 첫 화면도 동일 폭으로 캡처했다.
- 테스트: 기본 `npm test`는 Node v26.5.0의 webstorage 충돌로 136개 실패/271개 통과였다. `NODE_OPTIONS=--no-experimental-webstorage npm test`로 다시 실행하니 29개 파일, 407개 테스트가 모두 통과했다. 앱 코드나 테스트 기대값을 바꾸지 않았다. 배포 환경과 개발/CI의 Node 버전을 고정할 필요가 있다.
- 배포용 빌드: `npm run build`가 성공했다. TypeScript 검사 및 정적 페이지 생성까지 완료됐다. 운영 배포를 실행한 것은 아니다.
- 테스트 통과는 임상 효과, 안전성 또는 개인정보 보호의 충분성을 입증하지 않는다.
- 실제 휴대폰, Safari, 화면 읽기 도구, 최신 위기 연락처 확인, 운영 배포 SHA 비교, P0 변경 후 회귀 검증은 아직 하지 않았다.
- 브라우저 흐름 검증에는 별도의 `127.0.0.1:3107` 작업 미리보기를 사용했다. 운영에서 이번 검토 중 새 기록을 시작하지 않았다. 검토 후 작업 미리보기에서 생성한 테스트 기록 1개를 UI로 지우고 ‘아직 남긴 기록이 없습니다’를 확인했다. 운영 기록은 삭제하지 않았다.

## Antigravity에 전달할 작업 요청

이 문서를 기준으로 P0 1~4를 먼저 구현해 주세요. 기존 감정 후보 규칙과 요약의 비진단적 경계는 유지하고, 변경 범위와 추가한 회귀 테스트를 알려 주세요. 모바일 375px·데스크톱 1280px 미리보기를 준비하고 테스트·빌드를 확인해 주세요. main 병합·푸시·운영 배포는 미리보기 검토와 사용자 승인 전에는 하지 마세요.

## 배포 승인 순서

1. 기준 작업본과 변경 파일 확인.
2. P0 항목의 실제 화면 및 저장 동작 검증.
3. 빠른 확인/깊은 관찰/중단/악화/지난 기록/내보내기·가져오기·삭제 비교.
4. 모바일·데스크톱·밝게·어둡게 캡처 및 테스트/빌드 확인.
5. 사용자가 미리보기 승인.
6. 승인한 커밋을 배포하고 Vercel의 실제 배포 SHA와 맞춘다.
7. 운영 화면을 새로 열어 같은 문구·흐름·저장 경계인지 확인한다. 기존 기록을 새 코드가 올바르게 읽는지도 확인한다.

현재 상태: **검토 완료, 앱 변경 및 배포는 보류**. Antigravity의 수정된 미리보기와 사용자 승인이 다음 단계의 조건이다.
